PROPOSED FUTURE REPOSITORY STRUCTURE — NOT YET APPLIED

Purpose
-------
This is a target layout for a future, deliberate migration. It is not the
current layout and it must not be applied by moving files until the canonical
35-case data contract, root compatibility launchers, tests, and deployment
entry point have been updated together.

Current migration constraints
-----------------------------
- Root-level cases.csv, ai_responses.csv, responsible_ai_log.csv, and memory/
  are currently canonical project data.
- Root-level app.py, data_validation.py, rule_checker.py, dashboard.py,
  run_diagnostics.py, and memory_keeper.py are compatibility launchers.
- The present repository has 35 verified cases, not a verified 50-case dataset.
- dashboard.xlsx, a Groq integration, and a public Streamlit deployment are
  proposed artifacts only; they are not verified by this repository.
- Packet Tracer files, credentials, and generated outputs must remain ignored.

Migration mapping
-----------------
Current root canonical data      -> data/raw/ or data/processed/ only after every
                                   reader, validator, dashboard service, CLI wrapper,
                                   test, and documentation reference is updated.
Current diagnose_prompt.md       -> docs/prompts/diagnose_prompt.md after diagnostics
                                   is changed to resolve the configured path.
Current root compatibility files -> retain as documented launchers, or replace with
                                   installed console scripts after a compatibility plan.
Current outputs/reports/*.png    -> remains generated and ignored.
Current reports/*.md/.docx       -> remains committed report material.

Required acceptance criteria before applying this layout
--------------------------------------------------------
1. A reviewed source for a 50-case dataset exists, or all documentation retains
   the current verified 35-case counts.
2. Every script reads data paths from one central configuration mechanism.
3. Root-launcher commands and installed-package commands both pass their tests.
4. python -m pytest tests -v, data validation, rule checking, and dashboard
   generation pass against the migrated data paths.
5. A human reviewer confirms every user-visible report claim, especially
   authorship, model provider, public deployment URL, and evaluation metrics.
